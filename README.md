# Медова Полонина — сайт пасіки

Сайт пасіки в с. Солочин (Свалявський район, Закарпатська область).
Каталог сортів меду з цінами, калькулятор вартості замовлення та форма заявки.

Зроблено на [Nuxt](https://nuxt.com) (це Vue). Сайт генерується статично — кожна
сторінка віддається готовим HTML, тому швидко вантажиться й нормально
індексується Google.

---

## Як запустити на своєму комп'ютері

Потрібен [Node.js](https://nodejs.org) версії 22 або новішої
(саме її очікує Nuxt 4 — на 20 збірка падає).

```bash
npm install      # один раз, встановити залежності
npm run dev      # запустити сайт локально
```

Далі відкрити <http://localhost:3000>. Сайт оновлюється сам, щойно зберігаєте файл.

## Що треба замінити перед запуском

> ⚠️ Пошта — єдиний канал зв'язку на сайті (телефон прибрано). Якщо адреса
> нижче не робоча, з вами неможливо буде зв'язатися.

Усі ці дані лежать в одному файлі — **`app/data/site.ts`**:

| Що                        | Поле                | Зараз                      |
| ------------------------- | ------------------- | -------------------------- |
| Пошта для замовлень       | `email`             | `medovaPolonyna@gmail.com` |
| Соцмережі                 | `instagram` та інші | порожні                    |
| Куди надсилати замовлення | `orderFormEndpoint` | порожнє — див. нижче       |

## Як змінити ціни або додати сорт

Усе в тому ж файлі **`app/data/site.ts`**, у списку `products`.

Змінити ціну — просто виправити число:

```ts
packagings: [
  { weightKg: 0.5, label: '0,5 кг', price: 320 },   // ← ось тут
  { weightKg: 1,   label: '1 кг',   price: 600 },
]
```

Додати новий сорт — скопіювати будь-який блок і виправити:

```ts
{
  slug: 'kashtanovyi',              // латиницею, без пробілів, унікальний
  name: 'Каштановий',
  summary: 'Короткий підпис під назвою',
  description: 'Розгорнутий опис: смак, колір, коли кристалізується.',
  harvest: 'червень — липень',
  badge: '',                         // '' або напр. 'Новинка'
  packagings: [
    { weightKg: 1, label: '1 кг', price: 520 },
  ],
},
```

Новий сорт з'явиться і в каталозі, і в калькуляторі автоматично — більше нічого
правити не треба.

**Важливо:** `weightKg` — це вага в кілограмах (100 г = `0.1`). З неї рахується
загальна вага замовлення, тому її варто вказувати правильно.

## Інші правки контенту

Усе там же, в `app/data/site.ts`:

| Що змінити                        | Список          |
| --------------------------------- | --------------- |
| Які сорти показувати на головній  | `featuredSlugs` |
| Три розповіді з фото на головній  | `story`         |
| Питання-відповіді (FAQ)           | `faq`           |
| «Наші правила» на сторінці пасіки | `advantages`    |

**`featuredSlugs`** — просто список `slug` тих сортів, що йдуть на головну.
Прибрати сорт звідти — видалити рядок; у повному каталозі він лишиться.

**FAQ** живе тільки на головній (секція `#faq`). Навмисне не дублюємо ці ж
питання на інших сторінках: однаковий текст на кількох адресах псує позиції в
пошуку.

## Як додати фото

Зараз замість фото стоять сірі заглушки з підказкою, яке саме фото туди потрібне.

1. Покласти файл у теку `public/images/` (створити її, якщо немає).
2. Знайти потрібний `<PhotoSlot …>` у файлі сторінки й дописати `src`:

```vue
<!-- було -->
<PhotoSlot hint="Головне фото: пасіка серед гір…" />

<!-- стало -->
<PhotoSlot src="/images/pasika.jpg" alt="Пасіка в Солочині" hint="…" />
```

Де які заглушки:

| Файл                        | Що потрібно                                    |
| --------------------------- | ---------------------------------------------- |
| `app/pages/index.vue`       | головне фото, 3 фото до смуг, фото сортів       |
| `app/pages/produktsiia.vue` | по фото на кожен сорт (усі 10 позицій)          |
| `app/pages/pasika.vue`      | 3 фото: вулики, рамка з сотами, качка меду      |
| `app/pages/kontakty.vue`    | 1 фото: як виглядає вхід на пасіку              |

**Про розмір файлів.** Фото прямо з телефона важать 3–6 МБ — сайт із такими
вантажитиметься дуже довго. Перед завантаженням стисніть їх, напр. на
[squoosh.app](https://squoosh.app) — до 200–400 КБ і ширини близько 1600 px.

## Як зробити, щоб замовлення приходили на пошту

Зараз форма працює у запасному режимі: відкриває поштову програму покупця з уже
заповненим листом. Це працює, але покупець мусить натиснути «Надіслати» сам —
частина замовлень так губиться.

Щоб замовлення приходили автоматично:

1. Зареєструватись на [formspree.io](https://formspree.io) — безкоштовно до 50
   звернень на місяць.
2. Створити форму, вказавши свою пошту.
3. Скопіювати адресу вигляду `https://formspree.io/f/xxxxxxxx` у поле
   `orderFormEndpoint` в `app/data/site.ts`.

Після цього обов'язково відправте тестове замовлення й перевірте, що лист дійшов
(зокрема теку «Спам»).

## Як опублікувати сайт в інтернеті

Сайт уже підключений до [Netlify](https://netlify.com) і збирається сам після
кожного пушу. Усі налаштування збірки лежать у `netlify.toml`, тому нічого
задавати в кабінеті Netlify не треба.

Зібрати вручну (напр. щоб перевірити перед пушем):

```bash
npm run generate
```

Готовий сайт з'явиться в теці `.output/public` — це звичайні файли.

Окремо треба купити домен (приблизно 300–600 грн на рік) — напр. на
[ukraine.com.ua](https://www.ukraine.com.ua) чи [imena.ua](https://imena.ua).
Після цього не забудьте вписати домен у `public/robots.txt`.

## Гілки: де що живе

| Гілка       | Що це                | Куди деплоїться             |
| ----------- | -------------------- | --------------------------- |
| `main`      | бойовий сайт         | справжня адреса сайту       |
| `dev`       | стейджинг            | окрема адреса на Netlify    |
| `feat/…`    | одна конкретна зміна | прев'ю, якщо відкрити PR    |

Правило одне: **у `main` нічого не комітимо напряму**. Усе спершу потрапляє
в `dev`, і лише перевірене йде в `main`.

### Звичайний цикл роботи

```bash
git switch dev && git pull        # взяти свіжий стейджинг
git switch -c feat/нова-штука     # гілка під одну зміну

# ... правки, перевірка через npm run dev ...

git add -A && git commit -m "Коротко, що зроблено"
git switch dev
git merge --no-ff feat/нова-штука
git push                          # Netlify збере стейджинг
git branch -d feat/нова-штука
```

Подивилися на стейджингу, все добре — викочуємо:

```bash
git switch main
git merge --no-ff dev
git push                          # тепер оновився бойовий сайт
git switch dev
```

### Як називати гілки

- `feat/` — нова можливість: `feat/calendar-autoplay`
- `fix/` — виправлення: `fix/mobile-header`
- `chore/` — налаштування, залежності, документація: `chore/branching`

### Чому стейджинг закритий від пошуковиків

Netlify сам ставить `noindex` на прев'ю пул-реквестів і на **старі** збірки
гілок, але найсвіжіша збірка `dev` індексувалася б нарівні з бойовим сайтом —
і Google бачив би дві копії. Тому в контекстах `branch-deploy` і
`deploy-preview` після збірки запускається `scripts/noindex.mjs`, який кладе
в сайт файл `_headers` із забороною індексації.

### Що треба увімкнути руками (один раз)

1. **Netlify** → Site configuration → Build & deploy → Branches and deploy
   contexts → у «Branch deploys» додати `dev`. Після цього з'явиться адреса
   виду `dev--назва-сайту.netlify.app`.
2. **GitHub** → Settings → Branches → Add branch ruleset для `main`:
   заборонити прямий пуш і вимагати пул-реквест. Це те, що технічно не дасть
   випадково залити недороблене в бойовий сайт.

## Що ще варто зробити (не входить у код)

- **Google Business Profile** — безкоштовна картка бізнесу в Google Картах. Для
  локального виробника вона часто дає більше клієнтів, ніж сам сайт.
- **Політика конфіденційності** — формально потрібна, бо форма збирає ім'я,
  телефон і адресу покупця.
- **Google Analytics** — щоб бачити, скільки людей заходить і звідки.

## Структура проєкту

```
app/
  data/site.ts              ← контакти, сорти, ціни (головний файл для правок)
  assets/css/main.css       ← усі стилі, кольори на початку файлу
  components/
    SiteHeader.vue          ← шапка з меню
    SiteFooter.vue          ← підвал
    PhotoSlot.vue           ← заглушка під фото
    PriceCalculator.vue     ← калькулятор + форма замовлення
    FaqAccordion.vue        ← питання-відповіді на головній
  layouts/default.vue       ← спільний каркас сторінок
  pages/
    index.vue               ← Головна
    produktsiia.vue         ← Продукція та ціни
    pasika.vue              ← Про пасіку
    dostavka.vue            ← Доставка й оплата
    kontakty.vue            ← Контакти
public/                     ← файли, що віддаються як є (favicon, robots.txt, images/)
scripts/noindex.mjs         ← закриває стейджинг від пошуковиків
nuxt.config.ts              ← налаштування Nuxt
netlify.toml                ← збірка, контексти деплою та редіректи
```
